# سیستم طراحی داشبورد مدیریت — «بوم داده» (نسخهٔ ۲)

این سند قرارداد ظاهری و حرکتی داشبورد مدیریت را توضیح می‌دهد. هر تغییری در
`app/static/css/dashboard-modern.css` یا `app/static/js/dashboard-modern.js`
باید با همین اصول و با تست‌های زیر سازگار بماند:

- `tests/test_dashboard_modern.py` — قرارداد ایستا (ساختار، رنگ‌ها، تم تیره، RTL)
- `tests/test_dashboard_modern_dom.py` → `tests/js/dashboard-modern.dom.test.js` — رفتار

---

## ۱) ایدهٔ اصلی: بوم، نه جعبه

نسخهٔ قبلی یک شبکهٔ **باکس** بود: هر عدد داخل یک کارت سفید با سایه و گوشهٔ گرد.
بازخورد کارفرما روشن بود: «طراحی باکس‌ها افتضاحه و باید کامل حذف بشه».

نسخهٔ جدید یک **بوم داده** است:

| قبل (باکسی) | حالا (بومی) |
| --- | --- |
| هر شاخص داخل کارت با قاب و سایه | شاخص‌ها روی خود صفحه، جدا شده با **خط مو** |
| عمق با `box-shadow` | عمق با **نور**: لایهٔ جوی، هالهٔ گرادیانی، بلاب متحرک |
| نمودار = چند میلهٔ ساده | **داده‌نمای واقعی SVG** (ناحیه‌ای + ستونی) با گرادیان و انیمیشن |
| عدد کوچک در گوشهٔ کارت | **تایپوگرافی درشت** با `clamp()` و ارقام جدولی |
| ورود کارت‌ها با fade ساده | **کروگرافی پله‌ای**: کشیده‌شدن مسیر، رشد فنری ستون، جاروی حلقه |

قاعدهٔ سخت: هیچ بلوکی `background:`، `box-shadow:` یا گوشهٔ گردِ کارتی ندارد.
استثنای عمدی تنها **نوار قهرمان** (`.hx-hero`) است: یک باند گرادیانی تمام‌عرض
با درخشش داخلی که کارت نیست، بلکه «نور» است.

## ۲) توکن‌ها

روی `#dashboardBox.hx-dashboard` تعریف می‌شوند و نسخهٔ تیره‌شان در
`dark-theme.css` زیر `body.dark-mode #dashboardBox.hx-dashboard` است.

| گروه | نمونه | کاربرد |
| --- | --- | --- |
| متن | `--hx-ink`, `--hx-ink-2`, `--hx-ink-3` | سرتیتر، متن، متن کم‌رنگ |
| خط | `--hx-line`, `--hx-line-2`, `--hx-grid-line` | خط مو، محور نمودار |
| جَو | `--hx-wash-1..4` | بلاب‌های گرادیانی بوم |
| لهجه | `--hx-blue … --hx-green` | `data-accent` روی هر بلوک |
| حرکت | `--hx-ease`, `--hx-ease-spring`, `--hx-dur*` | easing و زمان‌ها |
| ریتم | `--hx-gap`, `--hx-pad` | فاصلهٔ عمودی بلوک‌ها |

هیچ رنگ تیره‌ای در `dashboard-modern.css` نیست؛ همهٔ رنگ‌های تیره فقط در
`dark-theme.css` می‌آیند (قاعدهٔ `AGENTS.md`).

## ۳) نقشهٔ بلوک‌ها

```
#dashboardBox.hx-dashboard
└── .hx-dash                         بوم (position: relative, isolation: isolate)
    ├── .hx-atmos                    لایهٔ جوی: ۳ بلاب گرادیانی + گرید مو + نویز
    ├── svg.hx-defs                  گرادیان‌های مشترک (حلقه‌ها و نمودار ناحیه‌ای)
    ├── header.hx-head               عنوان، زیرعنوان، تراشهٔ «داده‌های زنده»، ساعت زنده
    ├── section.hx-hero              نوار قهرمان: اشتراک + حلقهٔ درصد + دکمهٔ تمدید
    ├── div.hx-ticker                تیکر بی‌پایان شاخص‌ها (با لبه‌های محو)
    ├── section.hx-podium            سه ستارهٔ ماه (با خط مو جدا می‌شوند)
    ├── section.hx-block             شاخص‌های کلیدی → .hx-metrics (۸ شاخص)
    ├── section.hx-block             نسبت‌ها → .hx-figures (۲ گیج + ترکیب پرسنل)
    ├── section.hx-block             نمودارها → .hx-chartblock ×۲ (ناحیه‌ای + ستونی)
    └── section.hx-block             جدول‌ها → .hx-boards ×۲ + .hx-foot
```

## ۴) ریتم بصری

- **خط مو**: جداکننده‌ها `border-inline-start`/`border-block-start` با `--hx-line`
  و ضخامت ۱px هستند؛ در گریدها، خانهٔ اولِ هر ردیف با `:nth-child(4n+1)` مرز
  نمی‌گیرد تا لبه‌ها تمیز بمانند.
- **فاصله**: `--hx-gap` بین بلوک‌ها (clamp ۲۸ تا ۵۲px) و `clamp(16px, 2vw, 26px)`
  داخل خانه‌های دیوار شاخص‌ها.
- **تایپوگرافی**: عدد قهرمان `clamp(3.2rem, 7.2vw, 5.2rem)`، مقدار شاخص
  `clamp(1.7rem, 2.7vw, 2.35rem)`، برچسب ۰٫۸۲rem، متا ۰٫۷۶rem. همهٔ عددها
  `font-variant-numeric: tabular-nums` دارند تا با شمارش نلرزند.
- **راست‌به‌چپ**: همه‌چیز با ویژگی‌های منطقی (`margin-inline`, `inset-inline-*`,
  `padding-inline`) نوشته شده؛ هیچ `margin-left/right` در این لایه نیست.

## ۵) داده‌نما (Data-viz)

| نمودار | فناوری | نکته |
| --- | --- | --- |
| پاس ساعتی — کاربران برتر | SVG ناحیه‌ای (`.hx-area`) | مختصات در Jinja محاسبه می‌شود؛ ترتیب راست‌به‌چپ (اولین نفر سمت راست) |
| اضافه‌کاری — کاربران برتر | ستون‌های CSS (`.hx-bars`) | ارتفاع با `--hx-h`؛ محور درصدی و نشان «بیشترین» |
| نسبت پاس / اضافه‌کاری | حلقهٔ SVG (`.hx-gauge`) | جاروی `stroke-dashoffset` با `--hx-p` |
| اشتراک | حلقهٔ بزرگ در قهرمان | همان مکانیزم، با گرادیان اختصاصی |
| ترکیب پرسنل | نوار سهم دو‌رنگ (`.hx-split`) | عرض بخش‌ها از `data-hx-part`/`data-hx-total` |
| سهم در جدول‌ها | نوار ردیفی (`.hx-meter--row`) | عرض از `data-hx-part`/`data-hx-whole` |

هیچ عدد یا نمودارِ ساختگی وجود ندارد؛ همهٔ مقادیر از `app/main.py` می‌آیند.

## ۶) حرکت (Motion)

| حرکت | تکنیک |
| --- | --- |
| ورود پله‌ای بلوک‌ها | `is-in` + `@keyframes hx-rise` با `animation-delay: calc(var(--hx-i) * 45ms)` |
| شمارش اعداد | `requestAnimationFrame` با easing `easeOutExpo` و حفظ ارقام فارسی |
| کشیده‌شدن مسیر نمودار | `pathLength="1"` + `stroke-dasharray: 1` → انیمیشن `hx-draw` |
| محو ورود ناحیه و رویش نقطه‌ها | `hx-area-in` (با `transform-box: fill-box`) و `hx-node-in` |
| رشد فنری ستون‌ها | `@property --hx-h` + `transition: --hx-h 1.1s var(--hx-ease-spring)` |
| جاروی حلقه‌ها | `@property --hx-p` + `stroke-dashoffset: calc(var(--hx-len) * (1 - var(--hx-p)))` |
| تیکر بی‌پایان | دو نسخهٔ یکسان از فهرست + `animation: hx-ticker 38s linear infinite` (توقف روی hover) |
| هالهٔ دنبال‌کنندهٔ نشانگر | `pointermove` → `--hx-mx/--hx-my` روی `[data-hx-spot]` |
| ریزتعامل‌ها | بلند شدن ملایم خانهٔ شاخص، چرخش آیکون، درخشش دکمه، پالس تراشهٔ زنده |

اصول:

1. **حالت پایه هیچ‌چیز را پنهان نمی‌کند** — اگر JS اجرا نشود، داشبورد کامل است.
2. `prefers-reduced-motion: reduce` همهٔ انیمیشن/ترانزیشن‌ها را خاموش می‌کند و
   مقدارها همان‌جای واقعی می‌نشینند.
3. اگر `IntersectionObserver` نبود یا خطا داد، تایمر امنیتی ۱٫۵ ثانیه‌ای همهٔ
   بلوک‌ها را نمایان می‌کند.

## ۷) حالت تیره و چاپ

- تمام قواعد تیره در `dark-theme.css` و زیر `body.dark-mode #dashboardBox …`
  هستند: توکن‌های بوم، متن‌ها، خطوط، نوارها، نقطه‌های نمودار و هالهٔ قهرمان.
- کلاس‌های قدیمی (`.dashboard-card`, `.dashboard-chart-card`,
  `.dashboard-table-card`, `.dashboard-quick-card`) روی مارک‌آپ باقی مانده‌اند تا
  لایهٔ جدول‌های موبایل و تست تم تیره سبز بمانند، اما در تیره هم
  `background: none; box-shadow: none` می‌گیرند — یعنی هیچ باکسی برنمی‌گردد.
- چاپ همیشه روشن است: لایهٔ جوی، تیکر و درخشش‌ها حذف و نوار قهرمان به سطح سفید
  با مرز مو تبدیل می‌شود.

## ۸) پیش‌نمایش بدون سرور

```sh
python preview/render.py     # ساخت preview/out/index.html با دادهٔ نمونه
python preview/serve.py      # http://localhost:8099/admin/dashboard
```

- `/admin/...` روی همان `index.html` نگاشت می‌شود تا منطق SPA داشبورد را فعال کند.
- `/static/...` از سیم‌لینک `preview/out/static` → `app/static` خوانده می‌شود؛ پس
  هر تغییری در CSS/JS با یک رفرش دیده می‌شود.
- خروجی `out-empty/` حالت خالی (بدون داده) را نشان می‌دهد.

## ۹) چه‌کار نکنیم

- ❌ افزودن `background`/`box-shadow`/گوشهٔ گرد به بلوک‌های محتوا (باکس‌سازی دوباره).
- ❌ ست‌کردن `display` برای `#dashboardBox` در CSS (منطق `toggleBox` می‌شکند).
- ❌ ست‌کردن رنگ با style اینلاین در JS (لایهٔ تم تیره را بی‌اثر می‌کند).
- ❌ پنهان‌کردن محتوا در حالت پایه برای ساختن انیمیشن (بدون JS محتوا گم می‌شود).
- ❌ محاسبهٔ عدد/هندسه در JS (همه‌چیز از قالب و سرور می‌آید).
- ❌ استفاده از ویژگی‌های فیزیکی `left/right/margin-left` در این لایه (RTL می‌شکند).
