# Hastama page parity matrix

**Audit date:** 2026-10-03  
**Reference:** FastAPI/Jinja2 under `app/`  
**Target:** Laravel + Vue under `laravel/`

This is a route-by-route inventory of the page-producing surface found in `app/main.py`, the Jinja templates in `app/templates/`, and the corresponding Laravel routes/controllers and Vue Router entries. A page is **not** marked `VERIFIED` merely because its Vue component exists or its class names are similar.

## Status vocabulary

Only these values are used in the page-status column:

- `NOT_STARTED`
- `AUDITED`
- `DIFFERENCES_FOUND`
- `CORRECTED`
- `TESTED`
- `VERIFIED`

`AUDITED` means source-level mapping was inspected; it does not assert browser parity. `TESTED` means the particular route/configuration check has test evidence, not that every state of the page passed. No page reached `VERIFIED` in this session because both applications could not be run side by side in a browser; see `PARITY_TEST_REPORT.md`.

## Supporting templates and routes

- `app/templates/partials/label_queue.html` is a **partial**, included by the kiosk and label rendering flow; it is not a page route.
- `/api/label/config` (GET), `/api/label/print-document` (POST), and `/api/queue/print` (POST) are Python print-support APIs, not page rows. Vue calls all three, but this checkout has no corresponding Laravel route/controller; a CSRF exemption entry is not a registered endpoint. The Laravel source fallback sends unmatched `api/*` paths to a 404 JSON response; PHP was unavailable to confirm the live response.
- `/download_pdf` is a download workflow, not a page. The checked-in Python implementation returns 503 because `finalReportUser.html` is absent; the Laravel controller documents the same intended response. It is not browser-tested in this session.
- `/favicon.ico`, `/sw.js`, `/robots.txt`, `/sitemap.xml`, `/api/date` and `/api/training/search` support page rendering/behavior but are not separate pages in this matrix.
- The Vue `StatusPage.vue` route was not part of the Python page set. Its `/` and `/status` routes were removed from the router; `/status` now resolves to Vue's not-found component, although the Laravel fallback's HTTP response code still needs parity work.
